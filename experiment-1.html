[ SECTION 01 // OBJECTIVES & INQUIRIES ]

Core Research Questions

Modern consumer GPUs provide immense compute capabilities but operate under strict VRAM ceilings. This investigation was conducted to empirically resolve four practical systems-engineering questions:

QUESTION 01 // FRAMEWORK EFFICIENCY

Which inference framework (vLLM, Hugging Face, SGLang, or llama.cpp) provides the best speed and operational reliability on an 8 GB consumer GPU?

QUESTION 02 // WEIGHT QUANTIZATION

How much physical VRAM and token generation throughput can be gained through modern K-quants and importance-matrix (i-matrix) algorithms before crossing the quality collapse boundary?

QUESTION 03 // KV-CACHE PRECISION

How does key/value cache precision (f16, q8_0, q4_0) affect memory consumption and reasoning coherence under long-context (16,384 tokens) stress?

QUESTION 04 // SPECULATIVE PIPELINES

Can importance-matrix quantization paired with speculative decoding accelerate generation without unacceptable latency overhead or draft rejection?

SECURITY & INTEGRITY NOTE

All credentials, model tokens, and proprietary endpoints are strictly decoupled and omitted from this report. Environments rely on local weights, authenticated via ephemeral runtime environment variables.

[ SECTION 03 // EXECUTIVE FINDINGS ]

Executive Summary of Results

1. BEST SMALL-MODEL SERVING ENGINE

vLLM v1 Engine generated Qwen 2.5 1.5B at 102.71 tokens/sec, outperforming native Hugging Face (60.16 tokens/sec) by 70.7% (1.71x speedup) through continuous batching and PagedAttention.

2. BEST LOW-MEMORY LLAMA.CPP MODEL FORMAT

IQ3_M with Importance Matrix occupied just ~735 MB of storage, achieving ~182.3 tokens/sec with zero degradation in structural coherence or reasoning logic.

3. BEST STANDARD QUANTIZATION BALANCE

Q4_K_M slashed model disk footprint from ~2.92 GB down to ~0.91–1.10 GB (-68.8%) and increased token generation from 22.7 to ~59.9 tokens/sec (~2.64x faster).

4. OPTIMAL KV-CACHE PRECISION AT 16K CONTEXT

q8_0 halved key/value memory storage (~50% reduction) while maintaining 100% output fidelity. Conversely, q4_0 introduced severe numerical noise, causing catastrophic degeneration and infinite loops.

5. THE EXTREME COMPRESSION BOUNDARY (IQ2_XXS)

IQ2_XXS (2.06 BPW, ~481 MB, ~194.7 TPS) reached generation speed parity, but suffered from quantization collapse—hallucinating identities and looping uncontrollably.

6. THE 8GB LLAMA-3.1-8B ARCHITECTURAL CEILING

Hugging Face NF4 succeeded stably at ~30.20 tokens/sec (5.73 GB peak VRAM). vLLM AWQ repeatedly failed due to mandatory static pre-allocation of PagedAttention cache pools and workspace buffers.

7. SPECULATIVE DECODING MAXIMA

Fusing IQ3_M target + q8_0 KV-cache + Qwen 0.5B draft yielded ~189.4 tokens/sec generation and ~935.8 tokens/sec prompt ingestion—an 8.3x leap over unoptimized FP16 baselines.

KEY TAKEAWAY: SEPARATION OF WEIGHT VS KV-CACHE DECISIONS

Weight quantization and KV-cache quantization are completely distinct mathematical regimes. While weights can be safely quantized to 3.66 BPW (IQ3_M), quantizing attention state vectors to 4-bit (q4_0) corrupts self-attention dot-products across 16k tokens, causing catastrophic collapse. q8_0 is the true Pareto-optimal lower bound for KV caching.

[ SECTION 09 // ARCHITECTURAL INVESTIGATION ]

The 8GB VRAM Wall: Llama 3.1 8B Memory Allocation Postmortem

When evaluating Llama 3.1 8B on an 8GB GPU, a striking engineering dichotomy emerged: Hugging Face NF4 succeeds smoothly (~30.20 TPS, 5.73 GB peak), whereas vLLM repeatedly crashes with ValueError: No available memory for the cache blocks.

VRAM ALLOCATION WATERFALL // 8.0 GB PHYSICAL BUDGET (RTX 5060)
HUGGING FACE + BITSANDBYTES (NF4) ✓ SUCCESS
OS / WSL2 Driver Overhead ~1.1 GB
NF4 Quantized Weights (Dynamic) ~2.2 GB
Dynamic KV Cache (Batch=1, Seq=64) ~0.1 GB
Free Memory Headroom (STABLE) ~3.4 GB Headroom
Peak Allocation: 5.73 GB · Dynamic per-batch memory.
vLLM PRODUCTION SERVING ENGINE ✗ VRAM CRASH
OS / WSL2 Driver Overhead ~1.1 GB
AWQ Quantized Weights ~4.8 GB
PyTorch Workspaces & ZeroMQ IPC ~1.0 GB
CUDA Graph & Inductor Workspace ~0.8 GB
Remaining for Static Block Pool 0.3 GB (EXHAUSTED)
Available KV cache: -0.97 GiB · Cannot allocate PagedAttention block pool.
ARCHITECTURAL CAUSE: DYNAMIC ON-DEMAND VS STATIC PRE-ALLOCATION

Hugging Face allocates memory strictly on demand. For batch_size=1, it reserves only the exact KV cache needed for that sequence. Conversely, vLLM is an enterprise continuous-batching server: on boot, it mandates reserving static block tables, CUDA graph workspaces, and IPC buffers. On an 8GB physical GPU where OS/WSL2 consumes 1.1 GB and AWQ weights take 4.8 GB, the remaining 0.3 GB headroom is mathematically insufficient for vLLM's mandatory static block pool.

[ SECTION 10 // METHODOLOGY & CONCEPTS ]

Core Systems Principles & Rationale

MEMORY-BANDWIDTH BOUND DECODING

Autoregressive token generation on small models is strictly bounded by GPU memory bandwidth rather than compute FLOPs. Streaming a 735 MB model (IQ3_M) across the memory bus takes ~75% less time than streaming a 2.92 GB model (FP16), resulting directly in proportional speedups.

IMPORTANCE MATRIX (I-MATRIX) CALIBRATION

Instead of quantizing all tensors uniformly, i-matrix measures gradient activation sensitivity over representative text (wikitext-2). Sensitive channels retain higher bit-depth while non-critical weights are aggressively compressed, unlocking 3.66 BPW without loss of coherence.

SPECULATIVE DECODING MECHANICS

A lightweight draft model (Qwen 0.5B Q4) speculatively proposes 5 candidate tokens in parallel. The heavy target model (Qwen 1.5B IQ3) verifies all 5 tokens in a single forward pass, bypassing sequential token-by-token generation overhead.

BLACKWELL ARCHITECTURE WORKAROUND (-DCMAKE_CUDA_ARCHITECTURES=89)

Because NVCC on WSL2 lacked native pre-compiled target support for Blackwell compute_120a, building with architecture flag 89 (Ada Lovelace) provided a stable, fully functional backward-compatible compilation path.

11 Errors, Roadblocks & Forensic Resolutions

6.1 MODEL DOWNLOAD & SHARD CORRUPTION
IncompleteSnapshotError / OSError: We couldn't connect to huggingface.co
SOLUTION: Interrupted download left partial shards; executed snapshot_download(resume_download=True) before enforcing local_files_only=True.
6.2 TORCHAUDIO / CUDA VERSION MISMATCH
TorchAudio CUDA version mismatch (CUDA 13.0 vs CUDA 12.8 wheel conflicts)
SOLUTION: Reinstalled aligned PyTorch wheel index builds matching host CUDA 12.8 runtime explicitly.
6.3 TORCHAO & FLASHINFER SM_120 WARNINGS
Failed to load torchao/_C_mxfp8.so · SM 120 requires CUDA >= 12.9
SOLUTION: Binaries targeted Hopper (sm_90); runtime safely fell back to standard PyTorch kernels and FlashAttention-2.
6.4 VLLM ZEROMQ HANDSHAKE TIMEOUT
KeyboardInterrupt inside zmq/sugar/socket.py during vLLM v1 EngineCore startup
SOLUTION: Extended IPC readiness timeout via os.environ["VLLM_ENGINE_READY_TIMEOUT_S"] = "120".
6.5 VLLM CACHE-BLOCK EXHAUSTION ON 8GB
ValueError: No available memory for the cache blocks across 5 tuning passes
SOLUTION: Tested gpu_mem reduction, context restriction (max_len=2048), and eager mode. Concluded 8B models require 12GB+ on vLLM; used Hugging Face NF4 for 8GB single-batch inference.
6.6 SGLANG DEEPGEMM / JIT SM_120 INCOMPATIBILITY
NVCC >= 12.9 required by DeepGEMM on sm_120 architecture
SOLUTION: Set SGLANG_DISABLE_DEEP_GEMM=1 and SGLANG_ALLOW_OVERRIDE_SM=1; determined vLLM provided superior turnkey stability on RTX 5060.
6.7 NVCC COMPILATION FATAL ERROR (compute_120a)
nvcc fatal: Unsupported gpu architecture 'compute_120a'
SOLUTION: Reconfigured build with cmake -DGGML_CUDA=ON -DCMAKE_CUDA_ARCHITECTURES=89 to compile using compatible Ada Lovelace instruction sets.
6.8 CALIBRATION ESTIMATED AT 3 HOURS ON CPU
llama-imatrix calibration run estimated ~3 hours for 4,918 chunks
SOLUTION: Rebuilt llama.cpp with CUDA enabled and offloaded all layers to GPU via -ngl 99; calibration completed in ~35 minutes.
6.9 DATASET DOWNLOAD 401 UNAUTHORIZED / 404 NOT FOUND
Direct calibration dataset URL changes returned 401 Unauthorized / 404
SOLUTION: Extracted dataset archive locally from verified mirror; decoupled authentication tokens from documentation repository.
6.10 KV-CACHE QUALITATIVE COLLAPSE AT 4-BIT
q4_0 KV-cache produced random characters and infinite looping at 16k context
SOLUTION: Adopted q8_0 as the mandatory lower bound, halving KV memory footprint while preserving 100% output fidelity.
6.11 SPECULATIVE DECODING CLI FLAG DEPRECATION
Legacy --draft CLI option failed in current llama.cpp build
SOLUTION: Upgraded syntax to current --model-draft and --spec-draft-n-max 5 options with explicit GPU offloading.
[ SECTION 12 // FINAL TAKEAWAYS ]

Conclusions & Systems Trade-offs

There is no singular "silver bullet" inference framework for an 8 GB consumer GPU. Real-world deployment requires balancing memory footprint, quality retention, startup overhead, and serving throughput:

SERVING ENGINES
vLLM for Small Models
Unbeatable 102.7 TPS throughput with continuous batching for 1.5B models; requires 12GB+ for 8B models.
MODEL COMPRESSION
IQ3_M + Importance Matrix
The ultimate 735 MB sweet spot on llama.cpp, delivering 182 TPS with zero reasoning degradation.
SCALED INFERENCE
Speculative Decoding + q8_0
Achieves 189.4 tok/s generation and 935.8 tok/s prompt ingestion across 16k context windows.
